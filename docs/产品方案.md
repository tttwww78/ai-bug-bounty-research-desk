# AI 漏洞赏金研究台：产品方案与落地边界

## 判断

把“AI 自动挖洞”收窄成“新手可复核的漏洞赏金研究工作台”。用户真正要拿到的结果应是一个有授权记录、有证据、有人工复现、有可读报告的研究闭环；AI 只做资料整理和假设生成。

抖音网页可读取到标题、页面章节摘要和评论，但没有可读字幕；因此以下对应的是页面摘要，不是逐句视频转录。页面列出准备项“电脑、Agent 工具（豆包或 WorkBuddy）、补天账号”，实战步骤是“选择测试目标、信息收集、漏洞验证、报告提交”。本方案保留其短流程与实操产物，把“选目标”具体化为先核对官方规则和精确范围，并把首次练习导向安全靶场。

## 三步用户路径

### 第一步：确认授权

记录官方项目链接、规则更新时间、精确域名、允许路径、排除资产、禁止行为、频率限制和授权备注。范围缺失、冲突、已过期或项目授权不明确时，不进入目标测试。

### 第二步：整理资料，生成线索

从本人在授权项目中的正常操作导出 HAR/Burp 元数据，或导入 OpenAPI/必要源码。工具默认只保留必要元数据；AI 以证据、推断、缺失信息、误报风险分栏输出待验证线索。

### 第三步：人工验证，写出报告

只用本人控制的测试账号或本地靶场，在官方规则允许时进行最小化人工验证。记录预期/实际结果和脱敏证据。满足人工复现和范围核对后，导出报告材料；用户本人登录平台、再次检查政策并提交。

## 方案取舍

| 方案 | 好处 | 代价 | 结论 |
|---|---|---|---|
| 本地研究台：范围、资料、AI 线索、人工验证、报告 | 可解释，授权判断与关键操作留在人手里；适合新手 | 不会自动扫描，仍需要学会手工验证 | **本版采用** |
| 靶场学习模式：课程、练习记录、术语解释 | 练习环境边界清楚，适合首次上手 | 需要新增挑战内容和进度系统 | 后续候选；先用 PortSwigger Academy / Juice Shop |
| 自主扫描/利用 Agent | 自动化程度高 | 范围误判、请求副作用、提示注入、凭据/数据外传和平台违规风险高；复杂度大 | 不纳入本版 |

## 本版已落地

- Windows 本机运行的 Streamlit 单用户工作台，绑定 `127.0.0.1`。
- 项目授权台账、HAR/Burp/OpenAPI/Java 静态资料导入、AI 提示词、线索管理、报告/截图和奖励状态追踪。
- 补天登录和项目选择由用户在自己的浏览器完成；研究台不接管浏览器，也不读取登录态。
- 用户手工填写并确认项目规则、精确域名和允许路径；不把“登录成功”或“网页可访问”当作授权证明。
- 新手可直接登记 PortSwigger Academy 的具体练习 URL；代码校验 HTTPS 和 `web-security-academy.net` 后保存精确主机，不接受通配符或其他域名。
- AI 输出只能成为待验证线索；规则声明与授权勾选均不被程序伪装成独立核验。
- 目标侧唯一请求是用户再次确认后执行的一次 HTTPS HEAD：精确主机、443 端口、不带查询参数、无 Cookie/Token、不跟随跳转。
- 路径范围只接受明确的路径或末尾 `/*`；含歧义编码、复杂通配符或无效规则时拒绝检查。
- Java 源码只在内存中提取映射元数据，不落盘；提示词将项目资料明确标成不可信输入，并要求忽略资料中的指令。
- 远程 AI API 必须 HTTPS；本地 HTTP 仅限 loopback。调用前需勾选数据发送确认，响应体上限 2MB，禁止 HTTP 重定向。
- AI 入口保持可替换：复制提示词到用户选择的 Agent，或由用户配置 OpenAI-compatible API；本版没有豆包/WorkBuddy 专用 API 或浏览器控制集成。

## 参考项目与使用边界

### 适合学习的权威资料

- [OWASP Web Security Testing Guide](https://github.com/OWASP/wstg)：提供测试方法；报告引用测试项时固定版本编号，避免链接随最新版漂移。
- [OWASP API Security Top 10](https://owasp.org/API-Security/)：适合把线索映射到对象级、功能级和属性级授权、认证等风险类别。
- [OWASP ASVS](https://github.com/OWASP/ASVS)：验证要求基线，适合后续把产品线索卡扩展为可追溯检查项。
- [PortSwigger Web Security Academy](https://portswigger.net/web-security)：官方说明提供免费课程与交互实验，作为第一次动手练习入口。
- [OWASP Juice Shop](https://github.com/juice-shop/juice-shop)：故意包含漏洞的训练应用，适合本机隔离环境练习；不要将其部署到公开网络。

### AI Agent 仓库审阅结论

- [Trigii/pentagent](https://github.com/Trigii/pentagent)：README 提到 `scope.yaml`、明确授权开关、ScopeGuard 和哈希链审计日志，这些是可借鉴的门禁/留痕设计；同一仓库也提供 nmap、ffuf、nuclei、sqlmap 等工具，并包含利用和迭代循环，因此**不直接安装或接入本新手版**。
- [H-mmer/pentest-agents](https://github.com/H-mmer/pentest-agents)：README 描述了多 Agent、CLI、MCP、自主 hunt loop 和 exploit chain builder，规模很大，依赖外部平台凭据与安全工具；只用来理解生态，不适合作为当前项目的基础依赖。

### 可借鉴的 Skill

- [OpenAI Codex Security `triage-finding`](https://github.com/openai/plugins/blob/main/plugins/codex-security/skills/triage-finding/SKILL.md)：定位是对已有漏洞报告/扫描结果做静态证据分级，不负责发现漏洞、运行 PoC 或做动态验证。适合未来把“AI 线索”转成“证据缺口清单”，不替代人工复现。
- [yafet-dev/bugbounty-codex-skills](https://github.com/yafet-dev/bugbounty-codex-skills)：按漏洞类别组织研究 Skill，README 介绍了假设生成、差异实验和最小证明方法。作为候选方法库阅读；它覆盖的内容包括账号接管、DoS、RCE 等高风险类别，下载或安装前应先逐个审阅具体 Skill 与脚本，本版不安装。
- [superagent-ai/skills 的 `skill-security`](https://github.com/superagent-ai/skills/tree/main/skills/skill-security)：面向第三方 Skill 的静态扫描和人工语义复核流程，可作为后续审阅 ZIP/GitHub Skill 的工具候选；扫描分数不能代替人工判断。
- [OWASP Secure Agent Playbook：Prompt Injection Testing](https://github.com/OWASP/secure-agent-playbook/blob/main/plugins/ai-security-skills/plays/prompt-injection-testing.md)：适合后续为“导入资料里夹带指令”的场景补充安全评估；该页面是测试方法，不是生产提示词。

## 提示词设计原则

- 把官方规则、接口名称、导入内容与线索视为不可信数据，不能让资料里的文字改写模型指令。
- 输出事实、推断、假设、缺失证据和置信度，不得把 AI 置信度写成漏洞成立或严重度结论。
- 在授权信息不足时停止给目标侧验证步骤；只允许提出本地靶场/自有账号的最小化人工验证。
- 不调用工具、不联网、不扫描、不利用、不读第三方数据、不提供持久化/数据外传步骤。
- 不承诺挖到漏洞或获得赏金；所有报告必须由用户人工复现并核对官方当前规则。

完整提示词见 `prompts/security_analysis_prompt.txt`，应用内复制提示词与可选 API 调用共用同一份指令文件。这个提示词是为本项目的静态资料分析写的，不能让目标 Agent 自动打开网址或执行命令。

## 尚未实现的候选

- 官方范围规则的版本快照与到期提醒（目前由用户手工维护）。
- 本地靶场引导页和学习记录（不接触真实资产）。
- 更完整的文件/图片格式验证、数据库加密与自动备份。
- 针对目标范围解析和脱敏规则的独立单元测试及人工 UI 验收。

## 本地使用技能参考

- `agent-reach`：搜索公开资料/GitHub 的路由技能；本次 `doctor --json` 在 12 秒上限内未返回结果，因此通过公开页面和官方仓库源码/README 补足核验。
- `security-and-hardening`：用于本地应用的上传、API 外发、提示注入和最小数据保存边界。
- `first-pass-acceptance`：可用于后续功能交付时列出验收锚点；本次不把静态文档或语法检查当成用户验收。
